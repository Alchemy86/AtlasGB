# Below the game — Pokémon Red/Blue

[← Pokémon Red/Blue](../README.md) · [by address](by-address.md) · [by name](by-name.md) · [the structures](structures.md) · [AtlasGB](../../../README.md)

High RAM is 127 bytes the CPU can reach one byte faster than anything else, and Gen 1 spends
them on the things that run every frame: the joypad, the frame counter, the current ROM bank,
the divider-fed random seed.

**The OAM DMA routine has to live here.** While a DMA is in progress the CPU cannot read the
cartridge or work RAM, so the loop that waits for it must sit somewhere that stays readable —
which is why every Game Boy game copies a few bytes of code into high RAM at boot.

The stack is the other entry worth reading twice. Its section is `$DF00-$DFFF` and its only
label, `wStack`, sits at `$DFFF`, because the stack pointer starts at the top and grows
*downwards* through all 256 bytes. The atlas records the 255 bytes below it as *reached by no
label* rather than as a hole — which is the honest description, and is why the coverage table
adds up.

`wPredefID` and its three saved register pairs are Gen 1's answer to calling a routine in
another bank: put an id in the byte, and `Predef` looks it up, banks it in, and restores the
registers afterwards.
