# Adding an atlas

[← AtlasGB](../README.md) · [the schema](schema.md) · [verification](verification.md) ·
[provenance](provenance.md)

AtlasGB has one atlas today — [Pokémon Red and Blue](../atlases/pokemon-rb/) — and the
layout exists so that it has room for more. This page is what a second one costs.

It is deliberately explicit about the expensive part. **Producing a table of addresses is
easy and worth almost nothing**; every wiki already has one. What makes an atlas worth
publishing here is that each row carries evidence somebody can check, and that the rows
with no evidence say so. If you are not going to do the evidence, what you have is a
transcription, and this project exists because transcriptions are unauditable.

---

## The terms, before you start

Know this at the top rather than at the pull request, because it is not something anybody
should discover late.

**An atlas you contribute is published under [CC BY-SA 4.0](../LICENSE-CC-BY-SA)**, like
every other atlas here: your rows, your descriptions, your evidence record and your prose.
Anyone may use it, and anyone who publishes an improved or extended version of it must
credit AtlasGB and release theirs under the same terms. You keep your copyright; you are
licensing, not assigning.

**The extractor and the chapter rules you write go in [`tools/`](../tools/) and are
[MIT](../LICENSE)**, like the rest of the tooling. That is deliberate: your extractor is
the most reusable thing in your contribution, and the next cartridge's author should be
able to start from it without a condition attached.

**The schema is MIT too**, which is the part that matters most here: you do **not** need
to publish inside this repository to produce a compatible atlas. Implement
[`schema/atlas.schema.json`](../schema/atlas.schema.json) wherever you like, under whatever
terms you like. A second compatible atlas somewhere else is worth more to everybody than an
exclusive one here — that interoperability is why this page exists.

[licensing.md](licensing.md) is the path-by-path table and the reasoning behind the split,
including why the addresses and the symbol names are not ours to gate in the first place.

## What an atlas is

A directory under [`atlases/`](../atlases/), named for the cartridge, holding everything
specific to it and nothing else:

```
atlases/<id>/
  meta.json              identity: which game, which engine, which disassembly
  README.md              its front page — generated blocks plus your prose
  data/atlas.tsv         the source of truth. Everything else derives from it
  data/atlas.json        generated by tools/export.py
  data/atlas.min.json    generated by tools/export.py
  data/evidence.json     written by tools/apply-evidence.py when a run lands
  docs/by-address.md     generated index
  docs/by-name.md        generated index
  docs/structures.md     generated structure tables
  docs/<chapter>.md      one page per chapter — generated table, your prose
```

`<id>` is lowercase, digits and dashes: `pokemon-rb`, `pokemon-gs`, `zelda-la`. It is a
public URL, so pick it once.

**Nothing outside that directory is yours to fork.** The schema, the tooling, the
verification contract, the consuming guide and the brand are shared, and an atlas that
needed its own copy of any of them would be a sign the shared thing is wrong — fix the
shared thing.

The tools discover atlases by the presence of `meta.json`. There is no list to add
yourself to, because a list is a thing people forget, and the failure mode is an atlas that
quietly stops being validated.

## 1. `meta.json` — say which cartridge

```json
{
 "schema": "atlasgb-atlas/1",
 "id": "pokemon-gs",
 "title": "Pokémon Gold and Silver",
 "short_title": "Pokémon G/S",
 "platform": "Game Boy Color",
 "status": "published",
 "summary": "One sentence. It becomes the atlas's opening line and its JSON description.",
 "games": ["Pokémon Gold (English, USA)", "Pokémon Silver (English, USA)"],
 "engine": {"name": "Generation 2", "note": "why these games share one atlas"},
 "source": {"disassembly": "pret/pokegold", "url": "https://github.com/pret/pokegold"},
 "verified_by": {"repo": "...", "url": "...", "cartridge": "POKEMON_GLD"},
 "not_covered": ["the versions this atlas is *wrong* for, and why"]
}
```

`title`, `games` and `summary` are required and are checked by `tools/validate.py`, because
they are what every generated page, badge and JSON `meta` block is titled from. **A count
with no cartridge attached is meaningless**, and that is the failure this file prevents.

`not_covered` is not decoration. If a nearby release shifted its RAM — as Yellow did — then
an address from your atlas is *wrong* there rather than approximately right, and the
failure mode is a write landing in the middle of somebody else's data and passing its own
checksum. Say so by name.

## 2. `data/atlas.tsv` — the rows

Eleven tab-separated columns, exactly as [the schema](schema.md) specifies. That page is the
contract and it is shared: your atlas uses the same `region`, `role` and `verify`
vocabularies as every other one, so a consumer writes one parser.

Two rules the validator enforces and that are easy to get wrong:

- **The file must start with its header row, with no comment lines.** GitHub's TSV viewer
  has no notion of a comment: a preamble costs the file its sortable, searchable table
  view, which is most of what makes an atlas browsable without cloning. Provenance goes in
  prose, not in the data.
- **Work RAM and high RAM must be completely accounted for** — every byte named by a
  symbol, inside a `gap` no label reaches, or declared `free` by the linker. A hole in a
  memory map is a byte nobody looked at, and "nothing is here" and "nobody checked" must not
  look the same.

`region` covers the CPU's address ranges; if your cartridge uses a mapper or a region the
current vocabulary does not name, that is a change to the shared schema and should be
proposed as one.

## 3. The extractor — derive, do not transcribe

Eight of the eleven columns are *derived*; `desc`, `verify` and `related` are ours.
[`tools/extract.py`](../tools/extract.py) derives them for pokered by parsing the linker's
map file from a **built** checkout, and re-checks the ROM's SHA-1 first so an unbuilt or
patched checkout can never silently supply addresses for a different cartridge.

A different cartridge means a different disassembly, a different map file and a different
set of facts to read out of it, so it gets **its own extractor beside that one** —
`tools/extract-<something>.py`, sharing [`tools/mapfile.py`](../tools/mapfile.py) if the
map format is the same. Whatever you write must:

- take a path to a local checkout and **fetch nothing**;
- verify the built ROM against the disassembly's own published hash before believing a
  single address;
- rewrite only the derived columns, leaving `desc` and `verify` alone, so that a
  disassembly bump is a reviewable diff rather than a rewrite;
- report when the *set of symbols* changed, because that is exactly when the last
  verification run stops covering the file.

If your cartridge has no disassembly to derive from, stop and read the warning at the top
of this page again. Hand-typed addresses are the thing this project is a reaction to.

## 4. Chapters — group by subject

[`tools/chapters.py`](../tools/chapters.py) turns linker sections into subject chapters,
because a linker section is about where bytes *fit* and tells a reader nothing. That
grouping is editorial judgement and it lives as reviewable rules, not as thousands of
hand-typed cells. Add your rules there; a chapter with no entries is simply not rendered.

## 5. The evidence — the part that matters

This is what an atlas is *for*, and it is the only part this repository cannot do on its
own: proving an address against a running cartridge needs an emulator.

Read [verification.md](verification.md) for the tiers and the report format. The shape of
the work:

1. Run the cartridge under a cycle-accurate emulator with a fixed, reproducible script.
2. For every symbol in your atlas, decide which tokens it earned — `rom`, `live`, `inv` —
   and emit **every** symbol, including the ones that earned nothing. An omission would be
   read as a downgrade, and `apply-evidence.py` refuses a partial report rather than
   guessing.
3. Land it: `tools/apply-evidence.py report.json --atlas <id>`. That writes the `verify`
   column, records the run's provenance in `data/evidence.json`, and stores a SHA-256 digest
   of the column it produced.
4. CI checks that digest on every push. So a tier can never be edited by hand, and adding a
   symbol without re-running the verification turns CI red — correctly, because the atlas
   grew and the last run no longer covers it.

Include the top-level `"atlas": "<id>"` key in your report. It is optional for
compatibility with reports written before the project had more than one atlas, but with two
atlases in the repository a report that does not say which cartridge it is about is one
mis-typed flag away from attributing one cartridge's evidence to another.

**Entries you could not evidence stay marked as unevidenced.** That honesty is the product.
`tools/validate.py` prints them by name on every run so they cannot quietly disappear.

## 6. Generate, and check

```bash
tools/extract-<yours>.py --write        # the derived columns
tools/apply-evidence.py report.json --atlas <id>
make docs data                          # every page and every JSON export
make check                              # what CI runs
```

`make check` is red until every generated file agrees with the data, every link and anchor
resolves, and the evidence digest still names a real run. It is the whole review.

## What you actually have to hand over

A pull request adding an atlas is expected to contain:

| | |
|---|---|
| `atlases/<id>/meta.json` | filled in, including an honest `not_covered` |
| `atlases/<id>/data/atlas.tsv` | derived, not transcribed |
| an extractor in `tools/` | so the next disassembly bump is a rerun, not a re-do |
| chapter rules in `tools/chapters.py` | subject grouping for the new cartridge |
| a landed verification run | with `data/evidence.json` naming the emulator, the commit and the cartridge's SHA-1 |
| prose | the atlas README and whatever chapter pages you have written; generated tables come for free |
| green CI | `make check` |
| agreement to the terms | the atlas content under [CC BY-SA 4.0](../LICENSE-CC-BY-SA), the extractor and chapter rules under [MIT](../LICENSE) — see [the terms](#the-terms-before-you-start) |

**No commercial ROM data, in any form** — not a table of values, not a byte of the boot
ROM. The cartridge's own tables appear as *addresses*; the numbers at them are read from
the player's own cartridge at run time. See [licensing.md](licensing.md).

**Write every description from scratch.** A disassembly's prose and comments are its
authors' work and are not ours to copy, however freely its facts may be used. Addresses,
symbol names and structure layouts are facts about the cartridge; the sentences explaining
them are not.

## A partial atlas is welcome; a dishonest one is not

You do not need 100% coverage of everything to open a pull request. An atlas with a
complete work RAM map, a thin set of descriptions and one honest live script is a genuinely
useful thing, and it is roughly what Pokémon Red/Blue looked like on its first day — 370
descriptions out of 1,012 addresses, and it says so on its own front page.

What is not welcome is a row that claims more than was checked. Every tier is a statement
that a specific run, against a specific cartridge, observed a specific thing. Keep it that
way and the next atlas inherits a promise worth having.
