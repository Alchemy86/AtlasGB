# The story

[← AtlasGB](../README.md) · [by address](by-address.md) · [by name](by-name.md) · [the structures](structures.md)

**`wEventFlags` is 320 bytes and 2,560 single-bit events** — every gift taken, every trainer
beaten, every door unlocked, every one-off line of dialogue already heard. It is the largest
opaque region in the game and it is, quite literally, where you are in the story.

The mechanism is worth understanding because it generalises. A map script opens by testing a
flag and returning if it is set; that is how a cutscene plays once. So *setting* the right flag
skips a cutscene entirely — the first flag in the array is the one Pallet Town's script checks
before it lets you walk north, which is why setting bit 0 of byte 0 skips the whole
introduction, the starter choice and the rival battle, and is the cheapest way to get a brand
new game walking.

Beside it sits the **missable-object system**. `wToggleableObjectFlags` has one bit per object
that can be removed from a map — an item ball picked up, a boulder pushed — and
`wToggleableObjectList` is rebuilt from those flags every time a map loads. That is the
difference between an object that is gone and an object that is merely not drawn.

Each map also keeps its own script position, in its own byte, all of them inside the saved
block. That is why a story position survives a reset and a mid-cutscene state does not.
