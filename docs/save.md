# The save

[← AtlasGB](../README.md) · [by address](by-address.md) · [by name](by-name.md) · [the structures](structures.md)

A `.sav` is **raw cartridge RAM, bank 0 first, no header** — so a file offset *is* an offset
into a bank, and bank 1 begins at file offset `$2000`. There is nothing to parse.

`wMainDataStart` is the boundary that makes every write-side tool safe. Work RAM
below it is scratch; from it to `wMainDataEnd` is what a save writes out. **A tool that writes
only below that address cannot corrupt a save file however wrong it is**, because the bytes
never reach the medium the save is written from — the player has to walk into a Pokémon Center
and choose SAVE for that to happen. Battle control enforces exactly that boundary in code, and
the enforcement is tested by pointing its own write door at `$A000` and checking the byte does
not move.

Every saved block carries a checksum — the complement of a byte sum — and the boxes carry six
more, one per box per bank. Edit a save by hand and those have to be fixed, or the game
discards it and offers you a new game over the top of it.
